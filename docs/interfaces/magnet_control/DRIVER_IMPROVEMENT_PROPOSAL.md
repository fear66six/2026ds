# 驱动改进提案

本文件只提出兼容方案，不代表已实现，也不修改当前已验证驱动。

## 目标

在保留 `SerialTransport`、`STM32MagnetUART` 和现有方法语义的前提下，增加确定的设备选择、串行化、可观测性和可测试性。持续吸合协议必须另行评审固件，不能只在 Python 层循环续发。

## 建议项

| 当前问题 | 风险 | 建议接口 | 兼容性 |
|---|---|---|---|
| `preferred_linux_port()` 只按数量选择 | 误选或多设备无法部署 | `find_linux_ports(vid_pid=None, serial_number=None) -> list[PortInfo]`；配置层要求唯一匹配 | 保留旧函数，内部可调用新发现器 |
| 无命令事务锁 | 多线程回复错配 | 在 `STM32MagnetUART._command()` 使用 `threading.Lock`，文档仍建议单线程 | 不改变公开方法 |
| 无进程所有权 | 两个服务争用 | 可选 `PortLease`/lock file，记录 PID；失败明确报 owner | 默认关闭可保持兼容 |
| 无结构化日志 | 难追溯吸取/释放 | 注入 `logger` 或事件回调，记录单调时间、命令类型、参数、回复、耗时、结果；默认不记录敏感原文 | 构造参数采用可选默认值 |
| `ping()` 风格不一致 | 错误回复与设备离线不易区分 | 保留 `ping()->bool`；新增 `require_ping()->None` 严格异常 | 完全兼容 |
| 超时/断开无状态修复 | 上层可能继续使用半开连接 | 失败后将 client 标记不可用；只允许显式 `close()` 后重新 `open()`/握手 | 行为更保守，需回归测试 |
| Mock 与固件不一致 | 离线测试产生虚假信心 | 引入可注入 monotonic clock，模拟 deadline、FAULT、超长/错误回复；保留简单模式 | 保留现有默认行为或发布小版本说明 |
| 无自动测试套件 | 回归风险 | 增加纯离线 pytest/unittest：协议回复、边界、异常清理、并发拒绝、Mock 到期 | 不影响运行 |
| 500 ms 可能不足搬运 | 盲目续发会产生间隙或失控 | 单独设计 `LEASE_ON <ms> <seq>`/受限 `HOLD` + 通信看门狗；先做危害分析 | **协议变更**，需固件/驱动版本协商 |

## 推荐的兼容接口草案

```python
class STM32MagnetUART:
    # 保留全部现有方法。
    def require_ping(self) -> None: ...
    def get_capabilities(self) -> "Capabilities": ...  # 未来协议支持后再加

def find_linux_ports(
    *,
    vid_pid: tuple[int, int] | None = None,
    serial_number: str | None = None,
) -> list["PortInfo"]: ...
```

不建议把“物理释放成功”加入底层驱动，因为驱动没有视觉或传感器证据。应由上层状态机组合 `magnet_off()`、`get_status()`、机械动作和视觉结果。

## 迁移步骤

1. 锁定当前驱动行为和固件协议为基线测试。
2. 先增加不访问硬件的单元测试与更准确 Mock。
3. 增加可选日志、线程事务锁和严格 PING，不改现有调用。
4. 增加端口枚举信息对象；部署配置显式选择序列号，不静默选第一个。
5. 在独立测试分支验证超时、拔线、错回复、双进程和退出清理。
6. 只有搬运时长实测证明需要时，另立固件协议评审；协议版本化后再实现 HOLD/租约。
7. 经用户授权进行分阶段实机验证，确认后才替换生产入口。

## 所需测试

- 纯离线：50/500 边界，49/501/非整数拒绝；所有回复格式；退出和异常清理。
- Mock 时钟：开启后自动到期、跨 32-bit 计时边界、重复 ON 重置截止时间。
- 并发：两个线程不能交叉事务；第二进程得到明确占用错误。
- 端口发现：零/一/多设备、同 VID 不同序列号、断开重连。
- 故障注入：无 LF、非 ASCII、短写、拔线、延迟回复、错误回复、`FAULT=1`。
- 状态机：任何失败都停止机械动作并进入关闭/人工处理。
- 经另行批准的实机：只先测 `MAGNET_OFF`、PING、状态；负载启用需单独安全方案。
