# 项目复盘：从竞赛原型到可展示工程

## 一句话介绍

这是一个面向 2026 年大学生电子设计竞赛 E 题“拼图装置”的端到端机器人项目：系统观察散落碎片，求解目标拼法，再控制机械臂和电磁铁完成搬运与拼接。

**项目成果：全国大学生电子设计竞赛国赛一等奖。** 该奖项信息由项目负责人提供；公开仓库当前未附证书。

## 要解决的问题

真正困难的部分不是单个视觉算法，而是把多个存在误差和失效模式的环节串成一条可运行链路：

- 相机画面中的 A4 纸可能倾斜，边缘还可能轻微超出画面；
- 三类碎片需要不同求解方法，但不能各自维护一套互相冲突的硬件参数；
- 视觉坐标、纸面毫米坐标与机械臂坐标之间需要可追溯的标定关系；
- 机械臂反馈并不总能作为稳定的生产到位信号；
- 电磁铁必须在通信异常、程序退出或动作失败时可靠关闭；
- 竞赛现场需要快速启动、保留诊断证据，并避免误触发真实运动。

## 方案拆解

### 1. 用 A4 纸建立统一世界坐标

系统先检测工作区并完成透视校正，将后续算法统一到 `210 mm × 297 mm` 的纸面坐标。碎片轮廓、吸取点、目标位置和拼缝都先在这个坐标系中计算，再通过标定映射到机械臂坐标。

这个设计把“图像分辨率变化”和“机器人运动参数”隔开，使 Q1、Q2、Q3 可以共享执行链。

### 2. 为不同任务选择不同求解策略

- Q1 的碎片形状固定，重点是稳定识别、模板分类和刚体位姿规划；
- Q2 面对随机多边形，建立开放边并用 DFS/回溯搜索矩形组合，同时用角度、重合和尺寸约束剪枝；
- Q3 在几何边缘之外加入扑克牌花纹连续性评分，并用时间预算约束搜索。超时得到的 best-effort 结果只用于诊断，不进入真实运动规划。

### 3. 把真实执行做成显式、安全的状态转换

系统把仅规划与完整执行拆成 `plan` / `run` 两种入口。真实运行使用任务专属确认令牌，并按“观察—规划—抓取—抬升—转腕—搬运—下降—释放—回位”的分段流程执行。

电磁铁由 STM32 维护限时租约。上位机需要续租并确认状态；异常路径和退出路径都会尝试关闭，从协议层降低持续通电风险。

### 4. 让现场问题可以复盘

每次规划保存输入图像、叠加结果、场景 JSON 和动作队列。历史记录不被当作新条件下的证明，但它们能帮助回答三个关键问题：看到了什么、为什么这样规划、实际发送了什么。

## 可展示的工程能力

| 能力 | 仓库中的体现 |
|---|---|
| 计算机视觉 | A4 检测、透视校正、轮廓分割、模板分类、扑克牌花纹匹配 |
| 算法设计 | 刚体变换、多边形边匹配、DFS/回溯、几何剪枝、候选评分 |
| 机器人系统 | 手眼坐标映射、抓放位姿、腕部角度补偿、分段运动规划 |
| 嵌入式与通信 | K230 串口取图协议、NexArm UART、STM32 电磁铁协议与固件 |
| 工程质量 | Mock 后端、离线测试、配置集中化、错误处理、审计输出 |
| 现场交付 | 触控启动器、确认令牌、设备持久路径、调试与交接文档 |

## 已知边界

- 仓库含有与特定样机绑定的历史端口、标定和位姿，不能直接复制到另一台设备。
- Q1、Q2、Q3 的软件链路完成度不同；具体实机结论以 `docs/TODO_VERIFY.md` 为准。
- 历史运行里的“完成”主要代表指令流程完成，不代表动作后视觉验收已经完成。
- 获奖证书、现场视频和队员个人分工尚未纳入公开仓库；作为个人作品集发布时，建议补充本人负责范围。

## 面试讲述建议

建议围绕一条主线讲述：**如何把不稳定的物理系统变成可验证、可降级、可追溯的软件系统。**

可重点展开：

1. 为什么选 A4 纸面毫米坐标作为三套任务的公共接口；
2. Q2 的搜索空间如何通过几何约束缩小；
3. 为什么 Q3 的超时结果可以展示但不能驱动机械臂；
4. 为什么电磁铁采用租约，而不是简单的开/关串口命令；
5. 当机械臂反馈不可靠时，如何明确系统能证明和不能证明的内容。
