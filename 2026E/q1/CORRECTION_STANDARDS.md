# Q1 识别与规划判定标准

本文只描述单次桌面观察如何决定能否生成 `PieceMove` 队列。Q1 主流程不再做
逐片重拍、动作后视觉审计或自动纠偏。

## 1. 赛题与程序门限

| 标准 | 来源 | 用途 |
|---|---|---|
| 赛题评分 | `docs/E题_拼图装置.pdf` 第 2 页 | 相邻碎片对应顶点距离 ≤ 2 cm、无重叠、位置正确 |
| 识别/规划门限 | `SceneAnalyzer`、`plan_single_move` | 判断初始图像是否可生成机械臂目标 |

程序门限严于 2 cm 评分线，但不得为通过测试盲目放宽。优先修正相机标定、光照、
轮廓和模板对应关系。

## 2. 初始场景要求

单次图像必须同时满足：

1. `detect_paper` 找到 A4 四角和上下区域分界。
2. 全局模板分配能一一识别 P1、P2、P3、P4。
3. 每个待搬碎片状态为 `UNPLACED`，且位于 `UPPER_SOURCE`。
4. 已在目标区且满足放置门限的 `PLACED_OK` 可从队列跳过。
5. `MISSING`、`PLACED_OFFSET`、越界或匹配歧义会直接停止，不重拍、不自动修正。

## 3. 几何与位姿门限

| 检查 | 默认阈值 | 代码位置 |
|---|---:|---|
| 放置中心误差 | 5.0 mm | `SceneAnalyzer._classify_templates` |
| 放置角度误差 | 5.0° | `SceneAnalyzer._classify_templates` |
| 最大顶点/刚体残差 | 8.0 mm | `SceneAnalyzer`、`plan_single_move` |

规划使用完整刚体变换 `R,t`，将碎片中心映射为释放点，并分别计算
`pick_roll_deg` 与 `release_roll_deg`。不允许用镜像变换代替机械臂平面旋转。

## 4. 队列与执行

`plan_piece_moves` 按固定 P1 → P2 → P3 → P4 顺序生成队列。每项包含源/目标纸面
坐标、源/目标机械臂位姿、旋转量、刚体残差和置信度。

执行器负责源位姿反馈确认、磁铁吸合与续租、目标位姿反馈确认和释放。任一项失败
立即停止剩余队列并执行安全关闭。`final.json` 中 `completed=true` 仅表示队列执行
完毕，不是动作后视觉精度证明。

## 5. 离线检查顺序

1. 用实拍图确认 A4、分界线和四片一一匹配。
2. 检查 `scene.json` 的区域、顶点和匹配置信度。
3. 检查 `piece_moves.json` 的 P1..P4 顺序、刚体残差和纸面坐标。
4. 核对纸面到机械臂矩阵与腕部方向。
5. V-013 已由用户实机确认完成；当前
   `direct_pick_release_pose_verified=true`。变更高度或六维目标后重新验证。

生产运行只保存 `capture.png`，不再生成 rectified/overlay/cycle 调试图片。需要视觉
调试时使用离线测试或单独诊断工具，不把调试产物重新接回生产控制循环。

## 6. 禁止事项

- 不改 `PIECE_TEMPLATES` 顶点去迁就错误的机械臂坐标。
- 不把 `completed=true`、遥测变化或 STM32 锁存状态写成已证明物理吸取成功。
- 未经明确批准，不打开真实串口、不运动机械臂、不通电磁铁。
